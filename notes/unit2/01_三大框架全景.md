# Unit 2：三大 Agent 框架全景

## 先记住：框架不是 Agent 的必要条件

Agent 的本质仍然是模型、工具、状态和循环。框架的价值是减少重复编排，并提供成熟的日志、记忆、持久化和集成方式。

## 怎么选

| 框架 | 主视角 | 适合场景 | 核心对象 |
| --- | --- | --- | --- |
| smolagents | 行动与代码 | 快速工具型 Agent、代码组合、多 Agent | CodeAgent、ToolCallingAgent、Tool |
| LlamaIndex | 数据与检索 | 私有知识问答、RAG、数据型 Agent | Document、Index、QueryEngine、Workflow |
| LangGraph | 状态与控制流 | 分支循环、长流程、人工审批、持久化 | State、Node、Edge、StateGraph |

## smolagents

CodeAgent 用 Python 代码表达行动，便于组合循环、条件和计算；ToolCallingAgent 使用 JSON 风格调用。代码执行必须限制导入、文件和网络权限。

课程还覆盖：自定义工具、Hub 工具、检索 Agent、受管多 Agent、视觉和浏览器 Agent。

## LlamaIndex

典型数据流：Reader 加载 Document → Parser 切成 Nodes → Index 建立检索结构 → Query Engine 查询 → 包装成 Agent Tool。

FunctionTool 适合普通函数，QueryEngineTool 适合知识库查询。Workflows 用事件和状态组织多步骤或多 Agent 流程。

## LangGraph

- State：共享数据契约。
- Node：读取状态并返回更新的函数。
- Edge：决定下一节点，包括条件分支和循环。
- compile：检查图并挂载持久化、断点等运行能力。

最适合“部分步骤必须确定、部分决策交给模型”的混合工作流。
